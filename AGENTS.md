# TDC Regnskap

Books Checkin's monthly regnskapsbilag in Fiken: one sale, one purchase, and fri posteringer for payouts. Web app and CLI (`pnpm foring`) share the same code.

UI copy is Norwegian bokmål. Keep established product and accounting words: Fiken, Checkin, bilag, føre/bokføre, utkast, superføring, fri postering, mva, reskontro.

## Architecture

- **Static SPA.** Next.js `output: "export"`, served by nginx. No app server, database, or server-side secrets. Nothing renders per request: no Route Handlers that read the request, no cookies, no `router.refresh()` to fetch data.
- **Login** is OAuth with PKCE in the browser (`src/lib/fiken-browser-auth.ts`). The token lives in sessionStorage. Access is governed in Fiken.
- **Fiken API** has no CORS. nginx proxies `/api/fiken/*` to api.fiken.no (`docs/nginx-*.conf`); `next dev` does the same with a rewrite. The proxy holds no keys.
- **Shared core in `src/lib`** (PDF reader, recipe, plan, checks, Fiken client) is used by both the web app and `src/cli`. Keep it framework-free and pure where possible; UI and CLI are thin shells.
- **The recipe** is `regnskap.config.json`, parsed with the Zod schema in `src/lib/config.ts` and built into the app. Changing it means commit + deploy.

## Money and Fiken

- **Money is integer øre** everywhere. Parse and format at the edges (`formatNok` in `src/lib/plan.ts`). No floats in sums.
- **Fiken allows one concurrent request** and slows down above ~4 req/s. All calls go through the serial queue in `FikenClient` (`src/lib/fiken.ts`). Do not `Promise.all` Fiken requests or bypass the client.
- **Never write to Fiken without showing the plan and getting explicit confirmation.** Web: confirm dialog (and tick off failed checks first). CLI: `j`/`ja` prompt; `--yes` only when every check passed. Dry-run is the default.
- **Checks live in `src/lib/verify.ts`.** Add new cross-checks there (pure, unit-tested), not ad hoc in the UI or CLI.
- Refuse to book the same month twice (reference `Checkin YYYY-MM`).

## Tests and data

- Test fixtures are PDFs generated by `test/pdf-fixture.ts`. **Never commit a real regnskapsbilag** or numbers copied from one — they contain names and amounts. `*.pdf` is gitignored.
- Validate external input (config, CLI args, Fiken responses we depend on) with Zod schemas in `src/lib`. Do not hand-roll parallel validation that can drift.

## No pop-in

The first paint of a screen is the real screen.

- While the app boots or logs in, show `AppLoading` (logo + label). Do not flash “Henter…” and then swap in a different layout.
- Fiken data goes through TanStack Query. Mutations use `useMutation` and update the query cache. Do not hand-roll `busy` + `fetch` state for Fiken resources.
- Empty, error, and ready states each have a stable layout. An empty or error state is an illustration, a short heading, and one action (`ErrorScreen`, `src/components/illustrations.tsx`).
- If something must arrive later, reserve its box (skeleton of the same size). Do not grow the page when it appears.

## Browser defaults

Do not switch off native browser behavior: swipe back/forward, pull-to-refresh, pinch zoom, text selection, scroll bounce. No `overscroll-behavior`, `touch-action: none`, `user-scalable=no`, or touch `preventDefault` on page-level elements. Fix the specific layout bug instead.

## Interactive controls

Use the shared `Button` (`src/components/ui/button.tsx`) for anything the user should tap — including choice cards, not only primary CTAs.

- Affordance lives on `Button`: `cursor-pointer`, hover/active surface mix, focus ring, press scale (`btn-press`). A bare `<button>` with only `bg-[var(--color-bg-surface)]` reads as a dead panel.
- Choice / option tiles (e.g. picking a bilag from the inbox): `variant="surface"` plus layout overrides (`h-auto`, `items-start`, `justify-start`, `text-left`, `whitespace-normal`). Do not reimplement surface hover by hand.
- Writes to Fiken (“Lag utkast”, “Bokfør”) open the `AlertDialog` confirm; the cancel action is **Avbryt**.
- Raw `<button>` is fine only when the control is not meant to look like an action (e.g. a labeled checkbox row).

## Copy

Write labels the way an accountant in Fiken speaks: “Bokfør”, “Lag utkast”, “Bilag”, “Utbetaling”, not “Submit” / “Post entry”. Amounts as `1 234,56 kr`.
Keep blurb text short and useful — say what will happen in Fiken, not how the parser works.

## Icons

`src/app/icon.svg` is the source for every icon: a T-account (T-konto) built from the TDC "T", with TDC as the account name and balanced debet | kredit columns. The same drawing is `TdcRegnskapLogo` in `src/components/tdc-regnskap-logo.tsx` — keep them in sync. After editing, regenerate `apple-icon.png`, `favicon.ico`, and `public/icon-{192,512}.png`:

```sh
PLAYWRIGHT_MODULE=/path/to/node_modules/playwright/index.mjs node scripts/build-icons.mjs
```

Playwright is not a dependency here; point at any install. `CHROMIUM_PATH` overrides the browser (default: newest `~/.cache/ms-playwright` headless shell).
